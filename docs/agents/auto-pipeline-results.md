Full suite run: 115 items, 409 min of audio, 13 slices, 8 systems, frozen dev/test split. Machine: Apple M1 Pro,
32 GB. Results: `auto-full` (all systems), `auto-configured-full` (the calibrated profiles, composed per item, see
below), `auto-smoke` (smoke subset, 1 item per slice), `baseline-full` / `baseline-smoke` (turbo and eg2 only), all under
`benchmarks/suite/results/`. **The per-item files (`<name>.json`, `manifests/*.jsonl`) are local-only and git-ignored**:
they embed the reference transcripts (TED-LIUM is CC BY-NC-ND) and local paths, and the repo is public. What is committed
is `<name>.summary.json`, the per-slice/per-system aggregates without any text (`run_suite --summarize`); the `.json`
names used in the commands below (and `make_profiles`/`gate`, which read per-item rows) need the local files, see
"Reproduce". Profiles:
`transcribe/profiles.json`, generated by `make_profiles` from the full run's **dev** split. Every number below is
from the full run unless it says "smoke".

Systems: `turbo` = mlx-whisper turbo (today's default backend), `eg2` = EG2 (English only), `single-a` = Qwen3-ASR
1.7B alone, `single-b` = Whisper large-v3 alone, `fused` = both engines aligned with tie-break to engine A, `+pick`
= + Gemma 4 26B-A4B picker, `+verify` = + Whisper teacher-forced audio verify (margin 0.05), `+refine` = + gated
Claude refine, `configured` = what `--backend auto` now runs with the calibrated `profiles.json`.

Reading:
- **Qwen3-ASR alone is the best English engine** (beats turbo on 5 of 7 English slices on test; turbo wins en_meeting and en_phone) and **Whisper
  large-v3 alone the best Spanish auto engine**. Every calibrated profile is single-engine (see the profile section).
- `fused` equals `single-a` word for word by construction: without pick or verify every disputed span takes engine
  A's side; it only adds `[unclear]` marks.
- `+pick`/`+verify` help Spanish (es dev mean 3.64 → 3.28 → 3.19, CI upper bound +0.003 pts, just short of
  significant) and hurt English (`+verify` en dev 13.14 → 14.58, significantly worse).
- **en_meeting is the outlier**: every auto system deletes words the reference has (smoke item: 250 deletions of
  491 words vs 127 for turbo). The likely cause, from inspecting that one smoke item only: the Silero VAD gate
  (threshold 0.5, 30 ms pad) misses quiet far-field and overlapped talkers (18 s of reference speech outside VAD),
  and each ≤30 s chunk is transcribed for its dominant talker. Turbo sees the whole file. Profiles can't fix it (turbo is not an `auto` engine id); the next lever
  is the VAD threshold and padding (changing them invalidates the engine cache).
- Speech-free clips: 0 inserted words per minute for every auto system (turbo 15.0).

## Stages: help / harm (all items; harm rate = harmful regions / changed regions vs the reference)

| stage | help | harm | neutral | harm rate |
|---|---:|---:|---:|---:|
| pick | 335 | 277 | 99 | 39.0 % of 711 |
| verify (margin 0.05) | 323 | 591 | 170 | 54.5 % of 1,084 |
| refine | 1 | 0 | 0 | 1 edit |

- Verify's margin applies to **summed** window log-likelihoods, whose differences are usually several nats, so a
  margin of 0.05 lets verify override almost every pick it disagrees with and leaves ~0 spans unclear. Whisper
  large-v3 is both engine B and the verifier, so overrides lean toward Whisper's wording (spec §10 self-preference).
  On English, where Qwen3 is the stronger engine, that is harmful.
- Refine is nearly idle (1 target on Karpathy, 0 on the Spanish talk, 1 edit in 115 suite items): its targets are
  unclear runs (verify leaves none), term near-misses (suite items have no titles, so no terms) and low-confidence
  agreed words.

## Trust, speed, memory

- Trust Spearman vs per-file WER (test, n = 42): heuristic `0.5·(1 − agreement) + unclear_rate` 0.81 on `fused`,
  0.78 on `+verify`; fitted coefficients (now in `profiles.json`, least squares on 43 dev files of `+refine`) 0.81 /
  0.77. Single engines: Whisper alone 0.80 fitted (its word probabilities vary with quality); Qwen3 alone 0.15 (no
  word probabilities, agreement always 1.0). The configured profiles reach 0.44 overall: 0.24 on the Qwen3-only
  English files, 0.63 on the Whisper-only Spanish files.
- Speed: the suite's ×RT for auto systems is not usable (the systems share cached engine outputs, and up to five
  suite and real-audio processes plus a 15 GB VM shared the GPU with heavy swapping). Single-process engine speeds
  from the Task 0 spike: Qwen3-ASR 8.7–13.6 ×RT (4.4–6.9 min/h), Whisper large-v3 4.8–6.6 ×RT (9.1–12.5 min/h).
  Stage costs on real audio (contended): pick about 3 min per talk, verify 1.8–7.4 min per talk.
- Peak memory footprint (`/usr/bin/time -l`, whole process incl. Metal buffers). Full dual pipeline: **25.8 GB** on
  the 30-minute Karpathy talk before the fix below; **16.1 GB** on the 16-minute Spanish talk after it (the picker is
  ~13.4 GB). Those two runs differ in length and in the fix, so they are not a like-for-like comparison; the full
  pipeline's peak on 30-minute audio after the fix is **not measured** (pending). A single-engine profile never loads
  the picker or the verifier. The suite's `peak_rss_mb` (≤ 9.5 GB) undercounts Metal buffers.
- **Fixed during this run:** the engines never handed MLX's buffer cache back between chunks, so the footprint grew
  with audio length. `engines._transcribe_each` now clears the cache after every chunk. Like-for-like check, Whisper
  large-v3 engine alone on the 30-minute Karpathy audio (132 VAD chunks, idle machine): **25.7 GB without the clear,
  6.3 GB with it**, identical output (5,973 words) and speed (354 s vs 358 s, 5.2 ×RT).

Reason for every switch: fusion is not significantly better than the best single engine on dev (the paired
bootstrap CI upper bound must be < 0; Task 14 ruling), so pick, verify and refine go off with it. No stage rung beat
the best single engine significantly on any key either (best case: es `+verify`, CI [−0.87, +0.003] pts). Caveat:
the rule tests `fused`, which is identical to engine A by construction, so for keys where engine A is best fusion can
never win; testing the best chain rung instead would give the same result today.

How the configured numbers were produced: `auto-configured-full.json` takes each item's record from the ladder rung
its calibrated profile entry selects, using the profile key the probe actually assigned to that item (for example 5
of 9 en_meeting items probe as `en-noisy`). This is exact (each calibrated entry equals one rung) and avoids a second
multi-hour run.

## Dataset gaps and pending items

- **DER not measurable**: `HF_TOKEN` is not set, so diarization is skipped (every word is `Speaker 1`; the "DER" the
  runner prints for single-speaker output is meaningless). One-time step for the user: accept the terms at
  https://huggingface.co/pyannote/speaker-diarization-community-1 and set `HF_TOKEN` in `.env`, then rerun the
  en_meeting slice.
- **Code-switching**: no Spanish–English code-switching slice (Bangor Miami needs TalkBank terms); the `other` profile
  is unvalidated (Whisper large-v3 alone, no stages). The probe now calls audio code-switching (and routes it to
  `other`) only when at least 2 language windows disagree with the majority at confidence > 0.6; one dissenting window
  is LID noise.
- 3 gated Spanish dialects and music-only no-speech clips are missing (Task 1). Per-slice test sets are small (2–5
  items).
- Peak memory of the full dual pipeline on 30-minute audio after the cache fix: not measured (expected about the
  picker's 13.4 GB plus overhead, as on the 16-minute talk).
- Refine responses are not cached per (prompt version, input) as spec §8a asks; the suite memoizes picker answers and
  verify scores only.
- Next levers, in order: VAD threshold and padding for meetings; verify margin on the nats scale (1–4); a verify
  scorer that isn't engine B; a make_profiles rule that tests the best chain rung instead of `fused`.

## Known limitations from the final whole-branch review

- **Timestamps are approximate for Qwen3** (every English profile). Qwen3-ASR returns no word times: each chunk's words
  are spread over the chunk by character length, so SRT cues and word times are only as good as the VAD chunk bounds.
  `metadata.auto.timestamps` is `"approximate"` when the engine supplying the words has no native word times (Qwen3),
  `"engine"` otherwise (Whisper word times, Parakeet token times, EG2 frame times). **Pending: wire
  Qwen3-ForcedAligner** (the `mlx-audio` aligner) to get real word times; not done.
- **Verify window fixed, not re-measured.** The audio window scored by verify (and by the gated refine's audio check)
  used to span only the disputed words although the scored text includes up to 8 context words on each side. It now
  spans from the first left-context word's start to the last right-context word's end (same chunk; the scorer still
  pads 0.3 s). The verify harm numbers above (54.5 % of 1,084) predate this fix: **re-measure verify** (full dev run
  of `+verify`) before judging it again.
- **Trust is "uncalibrated" for every shipped profile.** `trust_score` reports `level: "uncalibrated"` and
  `estimated_wer: null` when the profile has no validated trust fit (`trust_spearman` missing or < 0.7 in
  `profiles.json`) or when the features cannot vary (a single engine without word probabilities: Qwen3, Parakeet,
  EG2). The measured Spearmans are 0.24 (English, Qwen3) and 0.63 (Spanish, Whisper), both below 0.7, so the CLI logs an
  INFO note instead of a low-trust WARNING. A calibrated estimate adds 0.05 and lowers its level one step for every
  skipped stage; skipped stages are always listed in `metadata.auto.trust.warnings`. `make_profiles` now writes
  `trust_spearman` per profile (dev rows of the rung the profile runs, at least 8 rows) and fits coefficients per rung.
- `[unclear]` markers appear only from Whisper low-probability words (Spanish and other languages), with no `| other`
  alternative: a single-engine profile has no second opinion.

## Reproduce

The per-item files are local-only. To regenerate them (needs network for the public corpora and the models):

```bash
.venv/bin/python -m benchmarks.suite.datasets prepare            # audio -> ~/.cache/whisper_translate/suite, manifests -> benchmarks/suite/manifests (git-ignored)
# ... run_suite / make_profiles as below, then publish only the aggregates:
.venv/bin/python -m benchmarks.suite.run_suite --summarize benchmarks/suite/results/auto-full.json   # writes auto-full.summary.json
```

```bash
S=mlx-whisper-turbo,eg2,auto:single-a,auto:single-b,auto:fused,auto:+pick,auto:+verify,auto:+refine
.venv/bin/python -m benchmarks.suite.run_suite --systems $S --manifest full --out benchmarks/suite/results/auto-full.json
.venv/bin/python -m benchmarks.suite.make_profiles --results benchmarks/suite/results/auto-full.json --write transcribe/profiles.json
```

Outputs are cached per system and item (`~/.cache/whisper_translate/suite/cache`), engine outputs per audio
(`~/.cache/whisper_translate/auto`), picker answers and verify scores in `.../suite/picker` and `.../suite/scorer`,
so a rerun only computes what changed. After `profiles.json` changes, the auto systems' cache keys change (the table
is part of the key); the rerun is cheap because engines, picks and scores are memoized.
